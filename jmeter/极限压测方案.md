# 12306 后端极限压测方案

## 目标

在当前本机环境下找出后端的稳定承载边界，并验证高并发场景下不会出现重复座位、订单缺明细、Redis 余票异常回滚、MQ 重复消费等核心一致性问题。

本轮压测结论只代表本机 Docker + IDEA 后端 + JMeter 同机运行环境，不等同于云服务器或生产环境上限。

## 阶梯设计

### 读接口阶梯

- `index12306-read-50.jmx`：基线读压测。
- `index12306-read-100.jmx`：已验证稳定的读压测。
- `index12306-read-200.jmx`：中高并发读压测。
- `index12306-read-500.jmx`：本机极限读压测。

读接口包含站点列表、车票查询、登录、乘车人查询、我的订单分页。重点观察吞吐量、P95/P99、后端 ERROR、数据库连接池和 Redis 响应。

### 下单链路阶梯

- `index12306-purchase-20.jmx`：已验证稳定的核心下单压测。
- `index12306-purchase-50.jmx`：本轮新增的下单极限探索。

下单链路会真实创建订单、锁定座位并消耗余票。每轮下单前需要确认测试车次、测试区间仍有足够余票；每轮结束后执行一致性检查 SQL。

### 混合流量

推荐组合：

- 读接口：`index12306-read-200.jmx`
- 下单链路：`index12306-purchase-50.jmx`

该组合模拟查询高峰下夹杂真实抢票请求，更接近业务场景。若本机资源不足，可降级为读 100 + 下单 20。

## 运行命令

```powershell
$env:JAVA_HOME='D:\Java\JAVASE21'
$env:Path="$env:JAVA_HOME\bin;D:\JMeter\apache-jmeter-5.6.3\bin;$env:Path"

jmeter -n -t D:\12306\jmeter\index12306-read-200.jmx -l D:\12306\jmeter\results\index12306-read-200-YYYYMMDD-HHMMSS.jtl
jmeter -n -t D:\12306\jmeter\index12306-read-500.jmx -l D:\12306\jmeter\results\index12306-read-500-YYYYMMDD-HHMMSS.jtl
jmeter -n -t D:\12306\jmeter\index12306-purchase-50.jmx -l D:\12306\jmeter\results\index12306-purchase-50-YYYYMMDD-HHMMSS.jtl
```

混合流量可以打开两个 PowerShell 窗口同时执行读接口和下单脚本。

## 停测标准

出现以下情况应停止继续升压：

- HTTP 5xx 或框架异常明显增加。
- PostgreSQL 连接池耗尽、Redis 超时、RocketMQ 消费持续失败。
- 下单接口出现非预期系统错误。
- 数据库出现重复物理座位、订单缺明细、订单状态和支付状态明显不一致。
- 本机 CPU 或内存长期打满，导致 JMeter 本身成为瓶颈。

## 一致性检查 SQL

按某一轮压测开始时间过滤订单，检查是否存在重复物理座位：

```sql
select train_id, carriage_number, seat_number, departure, arrival, count(*)
from t_order_item
where create_time >= timestamp '2026-07-31 20:00:00'
group by train_id, carriage_number, seat_number, departure, arrival
having count(*) > 1;
```

检查订单是否缺少订单明细：

```sql
select o.order_sn
from t_order o
left join t_order_item oi on o.order_sn = oi.order_sn
where o.create_time >= timestamp '2026-07-31 20:00:00'
group by o.order_sn
having count(oi.id) = 0;
```

统计本轮订单状态：

```sql
select status, count(*)
from t_order
where create_time >= timestamp '2026-07-31 20:00:00'
group by status
order by status;
```

统计物理座位占用是否异常：

```sql
select train_id, carriage_number, seat_number, count(*)
from t_order_item
where create_time >= timestamp '2026-07-31 20:00:00'
group by train_id, carriage_number, seat_number
having count(*) > 1;
```

## 结果记录口径

每轮记录：

- 脚本、并发数、用户池、开始时间。
- 总请求数、错误数、吞吐量。
- 核心接口平均耗时、P95、P99、最大耗时。
- 后端日志中的 WARN/ERROR 摘要。
- 数据库一致性检查结果。
