# 12306 智能客服知识库测试数据

> 说明：本文档为仿 12306 项目的测试知识库资料，用于验证文档上传、解析、切片、向量化、RAG 检索和智能客服回复效果。内容为业务模拟规则，不代表铁路官方最新规定。

## 适用范围

本文档覆盖账号登录、实名认证、车票查询、购票、支付、退票、改签、订单管理、乘车规则、智能客服意图识别、常见错误码和同义词检索词。建议在知识库分类中归入“客服业务规则”或“综合问答”。

## 一、账号与用户体系

### 1.1 注册与登录

用户可以通过手机号、用户名和密码完成注册。注册时应填写真实姓名、证件类型、证件号码和手机号。手机号用于接收登录校验、订单通知和支付结果提醒。

常见问题：

- 用户忘记密码时，可以通过绑定手机号完成密码重置。
- 用户更换手机号后，应先登录账号，再在“我的信息”中修改手机号。
- 如果用户无法登录，应先检查用户名、密码、验证码和网络状态。
- 如果系统提示登录态过期，用户需要重新登录。

客服回复建议：

- 当用户说“登录不了”“一直让我重新登录”“token 失效”时，应归类为登录异常。
- 优先建议用户重新登录；如果仍失败，再建议检查手机号、密码和账号状态。
- 不要让用户提供完整身份证号、银行卡号或支付密码。

### 1.2 实名认证

购票账号需要通过实名信息校验。实名信息通常包括真实姓名、证件类型、证件号码和手机号。一个乘车人信息必须与实际证件保持一致，否则可能影响购票、进站和退改签。

实名认证失败的常见原因：

- 姓名与证件号码不匹配。
- 证件类型选择错误。
- 证件号码包含空格、错位或末位 X 大小写问题。
- 账号中存在旧的乘车人信息，未及时更新。

处理建议：

1. 请用户核对证件类型、姓名和证件号码。
2. 如用户证件信息发生变更，建议先更新乘车人信息。
3. 如为临时证件、港澳台证件或护照，应提醒用户按页面支持的证件类型填写。

### 1.3 常用联系人与乘车人

用户可以维护常用乘车人，用于快速下单。常用乘车人包含姓名、证件类型、证件号、手机号和乘客类型。乘车人信息用于购票实名校验和订单明细展示。

业务规则：

- 添加乘车人后，购票时可以从列表中选择。
- 删除常用乘车人不会删除历史订单。
- 修改乘车人证件号后，已生成订单不会自动变更。
- 未完成实名认证的乘车人可能无法购票。

客服回复建议：

- 用户问“怎么给家人买票”，应提示先添加常用乘车人，再查询车次并下单。
- 用户问“联系人删了订单还在吗”，应回答历史订单仍保留。

## 二、车票查询知识

### 2.1 出发地与目的地

车票查询支持按车站查询，也可以通过省市选择定位到车站。省市只用于缩小车站选择范围，真正参与余票查询的是具体车站名称。

示例：

- 选择“江苏省 南京市”后，应展示南京、南京南等车站供用户选择。
- 选择“北京市 北京市”后，应展示北京、北京南、北京西、北京朝阳等车站。
- 只输入省份通常不能直接查到车次，因为车次售票区间按车站匹配。

客服回复建议：

- 用户问“为什么按省查不到票”，应解释需要选择具体出发站和到达站。
- 用户问“南京到上海怎么查”，应建议选择南京/南京南和上海/上海虹桥等具体站点。

### 2.2 查询日期

用户需要选择乘车日期。系统按乘车日期、出发站和到达站返回可售车次。若所选日期没有开行计划或尚未开售，可能查不到车次。

常见情况：

- 日期未到预售期，无法购买。
- 日期太近，部分席别售罄。
- 当天已过发车时间的车次不会作为可购车次展示。
- 节假日热门方向可能短时间售罄。

### 2.3 车次类型说明

车次类型通常包括高铁、动车、普速、特快等。不同类型车次在速度、停站、席别和票价上不同。

| 类型 | 常见前缀 | 特点 |
| --- | --- | --- |
| 高铁 | G | 速度快，常见席别有商务座、一等座、二等座 |
| 动车 | D | 速度较快，常见席别有一等座、二等座 |
| 城际 | C | 城市群短途运行较多 |
| 特快 | T | 普速列车，运行时间较长 |
| 快速 | K | 普速列车，票价相对较低 |
| 普客 | 无固定前缀 | 停站较多，运行时间较长 |

### 2.4 余票状态

余票状态用于表示某个车次某个席别当前可售数量。

常见展示：

- “有票”：余票充足或仍可购买。
- “少量”：余票较少，建议尽快下单。
- “无票”：当前席别不可购买。
- “候补”：可提交候补订单等待系统兑现。
- 数字：明确展示剩余票数。

客服回复建议：

- 用户问“无票还可以买到吗”，应解释可以关注余票刷新或尝试候补。
- 用户问“为什么刚看到有票提交就没了”，应解释余票是实时变化的，高峰期可能被其他用户先下单。

## 三、购票业务

### 3.1 在线购票流程

标准购票流程：

1. 选择出发站、到达站和乘车日期。
2. 查询车次列表。
3. 选择车次和席别。
4. 选择乘车人。
5. 可选：选择座位偏好或指定座位。
6. 提交订单。
7. 在支付时限内完成支付。
8. 支付成功后，订单状态变为已支付或已出票。

注意事项：

- 订单提交成功不等于购票完成，必须支付成功。
- 支付超时后订单会被关闭，席位和余票会释放。
- 同一乘车人同一时间段不应重复购买冲突车票。

### 3.2 选择席位

用户可选择席别，例如商务座、一等座、二等座、硬座、硬卧、软卧。若系统支持指定座位，用户可选择具体座位号；若所选座位已被占用，系统会提示失败或引导重新选择。

座位分配规则：

- 指定座位优先尝试锁定指定座位。
- 指定座位已占用时，不应自动改配其他座位，除非用户重新确认。
- 未指定座位时，系统按可用座位自动分配。
- 下单失败时，已扣减的余票和锁定的座位应回滚。

客服回复建议：

- 用户问“能不能选座”，应回答系统支持时可选择指定座位，未选择则自动分配。
- 用户问“为什么选的座位没有了”，应解释座位库存实时变化，提交时可能已被占用。

### 3.3 候补购票

候补购票是指当前无票时，用户提交候补需求。当有其他用户退票、改签或系统释放余票时，系统按候补规则尝试兑现。

候补规则：

- 候补不保证一定成功。
- 候补成功后，系统会生成订单并通知用户。
- 候补失败或截止时间到达后，候补订单会终止。
- 候补订单通常需要预授权或预支付，具体以系统流程为准。

客服回复建议：

- 用户问“候补多久能成功”，应说明无法承诺时间，取决于余票释放情况。
- 用户问“候补失败钱去哪了”，应说明未兑现的候补金额会按原支付渠道退回或解除预授权。

## 四、支付相关

### 4.1 支付方式

系统支持支付宝和微信支付。支付渠道字段建议统一为：

- `ALI_PAY`：支付宝支付。
- `WECHAT_PAY`：微信支付。

业务规则：

- 用户创建支付单后，应在订单支付时限内完成支付。
- 支付成功后，订单进入已支付状态。
- 支付失败时，用户可以重新发起支付。
- 支付渠道不应被错误识别，例如 `WECHAT_PAY` 不应当按支付宝处理。

### 4.2 支付异常

常见支付异常：

- 扣款成功但订单仍显示待支付。
- 支付页面关闭但订单未变化。
- 重复点击支付。
- 支付成功回调延迟。
- 订单已关闭后又收到支付成功通知。

处理原则：

- 支付成功回调应幂等处理，重复消息不应导致异常。
- 已支付订单再次收到支付成功消息，应保持已支付。
- 已关闭订单收到支付成功消息，不应直接改成已支付，应进入人工核查或退款流程。
- 用户扣款成功但订单未出票，应建议等待系统同步，仍异常时联系人工客服。

客服回复模板：

> 如果您已扣款但订单仍显示待支付，可能是支付结果同步延迟。请先刷新订单页面，稍等 1-3 分钟后再次查看。若仍未恢复，请保留支付凭证并联系客服核查。

## 五、退票规则

### 5.1 可退票条件

订单必须为已支付或已出票状态，且符合退票时间规则，才可发起退票。未支付订单不需要退票，可直接取消或等待超时关闭。

不可退票或需特殊处理的情况：

- 订单未支付。
- 订单已关闭。
- 订单已全部退款。
- 乘车日期或发车时间已超出线上可退范围。
- 订单明细与当前用户不匹配。

### 5.2 退票手续费

仿真规则如下，用于测试智能客服回答：

| 退票时间 | 手续费规则 |
| --- | --- |
| 开车前 8 天及以上 | 不收退票费 |
| 开车前 48 小时以上 | 按票价 5% 收取 |
| 开车前 24 小时以上、不足 48 小时 | 按票价 10% 收取 |
| 开车前不足 24 小时 | 按票价 20% 收取 |
| 开车后 | 通常不可线上退票，特殊情况按人工规则处理 |

客服回复建议：

- 用户问“我的票还能退吗”，应先判断订单状态和发车时间。
- 如果用户没有提供订单号，应说明需要订单号或具体车次日期才能判断。
- 如果知识库命中退票规则，应优先引用规则，不要编造具体订单状态。

### 5.3 全额退款与部分退款

全额退款：退整个订单下全部可退票明细。

部分退款：只退订单中的部分乘车人或部分座位明细。

业务规则：

- 全额退款时，可由后端按订单明细计算退款金额。
- 部分退款必须定位到具体订单明细，例如车厢号、座位号、乘车人或明细 ID。
- 退款金额应由服务端反查计算，不应信任前端传入的金额。
- 退款成功后，只释放对应座位和余票。
- 重复退款消息不应重复释放余票。

客服回复模板：

> 支持整单退票，也支持按乘车人或订单明细进行部分退票。实际可退金额需要根据订单状态、发车时间和退票手续费规则计算，请以系统最终展示为准。

## 六、改签规则

### 6.1 改签条件

改签用于变更乘车日期、车次、席别或到发站。改签必须基于已支付订单进行，且目标车次有余票。

常见规则：

- 开车前可尝试改签至其他有票车次。
- 开车后通常只能按规则改签当日部分车次，具体以系统支持为准。
- 已办理退票的订单不能改签。
- 已全额退款的订单不能改签。
- 改签后若新票价高于原票价，需要补差价。
- 改签后若新票价低于原票价，差额按支付渠道退回。

### 6.2 改签费用与差价

改签本身不一定收取手续费，但票价差额需要处理。

示例：

- 原票 553 元，新票 662 元：用户需补 109 元。
- 原票 662 元，新票 553 元：系统退回 109 元差价。
- 改签失败：原订单保持不变。

客服回复建议：

- 用户问“改签要钱吗”，应说明主要看新旧票价差额。
- 用户问“改签失败原票还在吗”，应回答原订单通常保持不变。

## 七、订单管理

### 7.1 订单状态

订单状态用于描述订单生命周期。

| 状态 | 含义 | 用户可见解释 |
| --- | --- | --- |
| 待支付 | 订单已创建但未支付 | 请在支付时限内完成支付 |
| 已支付 | 支付成功 | 订单已完成支付，可查看乘车信息 |
| 部分退款 | 部分明细已退款 | 部分乘车人或席位已退票 |
| 全部退款 | 全部明细已退款 | 该订单已全部退票 |
| 已完成 | 行程已完成 | 历史订单 |
| 已关闭 | 超时、取消或异常关闭 | 订单不可继续支付 |

### 7.2 查看订单

用户登录后，可以在“我的订单”查看自己的订单。订单查询必须基于当前登录用户，不允许用户通过修改请求参数查看他人订单。

安全规则：

- 前端应携带 token。
- 后端应从登录上下文识别当前用户。
- 查询订单时必须校验订单归属。
- 智能客服工具查询订单也必须按当前用户校验归属。

客服回复建议：

- 用户问“为什么我的订单看不到”，应先提示确认登录账号是否为购票账号。
- 如果刚支付成功，可能存在短暂同步延迟，可建议刷新或等待片刻。

### 7.3 取消订单

待支付订单可以取消。取消后订单关闭，已锁定的座位和余票应释放。

业务规则：

- 未支付订单取消不涉及退款。
- 已支付订单不能直接取消，应走退票流程。
- 超时未支付订单可由系统自动关闭。

## 八、乘车流程

### 8.1 进站流程

用户乘车前应完成实名制验证、安检和检票。通常需要携带购票时使用的有效证件。

流程：

1. 到达车站。
2. 使用有效证件进行实名核验。
3. 通过安检。
4. 查看候车室和检票口。
5. 按车站广播或屏幕提示检票进站。
6. 按车厢号和座位号乘车。

### 8.2 证件异常

如果身份证遗失、损坏或无法识别，用户应按车站规定办理临时身份证明或使用其他支持的有效证件。

客服回复建议：

- 用户问“身份证丢了还能坐车吗”，应提示可按车站规定办理临时身份证明。
- 不要承诺所有车站都能线上办理，应提醒以车站现场规则为准。

### 8.3 携带物品

乘车携带物品应符合铁路安全规定。危险品、易燃易爆品、管制器具等通常禁止携带。

客服回复建议：

- 用户问具体物品能不能带，应建议以车站安检和铁路公告为准。
- 对明显危险品，应明确提示不可携带。

## 九、智能客服 FAQ

### 9.1 购票 FAQ

Q：可以提前多久买票？

A：购票预售期以系统展示和铁路部门公告为准。建议用户在目标乘车日期进入预售期后尽早查询。

Q：为什么查得到车次但不能买？

A：可能是未到开售时间、该席别无票、车次停售、乘车日期不在可购范围，或账号实名信息未通过。

Q：提交订单后必须马上付款吗？

A：订单创建后需要在支付时限内完成支付。超时未支付时，订单会自动关闭，席位和余票会释放。

### 9.2 支付 FAQ

Q：扣款了但没有订单怎么办？

A：请先确认是否使用当前账号登录，再查看“我的订单”。如果支付成功但订单未同步，建议等待 1-3 分钟后刷新；仍异常时联系人工客服并保留支付凭证。

Q：重复支付了怎么办？

A：系统应按支付单和订单状态幂等处理。若确实发生重复扣款，应保留支付流水，由客服核查后按原支付渠道处理。

### 9.3 退改 FAQ

Q：已经发车了还能退票吗？

A：通常不支持线上退票，特殊情况需按车站或人工规则处理。

Q：退票多久到账？

A：退款一般按原支付渠道退回，到账时间受支付渠道影响。若长时间未到账，可联系支付渠道或客服核查。

Q：改签失败会影响原票吗？

A：通常不会。改签失败时原订单保持不变，用户仍可按原票乘车或重新尝试操作。

### 9.4 订单 FAQ

Q：为什么订单列表没有我的订单？

A：请确认当前登录账号是否为购票账号，并检查订单是否在历史订单或其他状态筛选中。如果刚支付成功，可能存在同步延迟。

Q：客服能帮我查订单吗？

A：智能客服可以在用户登录后查询当前账号下的订单，但不能查询其他账号的订单。

| 场景 | 用户提示 | 客服解释 |

| 登录过期 | 登录态已过期 | 当前登录状态失效，需要重新登录 |
| 无管理员权限 | 无管理员权限 | 当前账号不是管理员，不能访问后台功能 |
| 余票不足 | 当前席别余票不足 | 该席别已售罄或被其他用户锁定 |
| 座位已占用 | 指定座位不可用 | 座位库存实时变化，请重新选择 |
| 订单不存在 | 订单不存在或无权限访问 | 订单号错误，或订单不属于当前账号 |
| 支付失败 | 支付失败，请重试 | 支付渠道返回失败或网络异常 |
| 退款失败 | 当前订单不可退款 | 订单状态、发车时间或明细不符合退票条件 |
| 知识库无结果 | 暂未检索到相关知识 | 可换一种问法，或转人工处理 |

## 十一、意图分类标签

智能客服可将用户问题归类为以下意图：

- `ticket_search`：车票查询、余票查询、车次查询。
- `ticket_purchase`：买票、下单、选择乘车人、选择座位。
- `order_query`：查订单、订单状态、订单列表。
- `payment_issue`：支付失败、扣款未出票、重复支付。
- `refund_ticket`：退票、退款、退票手续费。
- `change_ticket`：改签、改签差价、改签失败。
- `account_login`：登录、注册、密码、登录态过期。
- `real_name_auth`：实名认证、证件信息、乘车人校验。
- `ride_rule`：进站、检票、证件丢失、携带物品。
- `admin_kb`：知识库上传、入库任务、向量化、后台管理。

## 十三、RAG 回复策略

### 13.1 命中知识库时

当检索结果包含明确规则时，智能客服应优先基于知识库回答。回答应包含：

1. 对用户问题的直接结论。
2. 命中的规则摘要。
3. 用户下一步应该做什么。
4. 如果涉及订单，提醒需要登录并按当前账号查询。

示例：

用户问题：“我的票还能退吗？”

建议回答：“是否可退需要看订单状态和发车时间。已支付订单通常可在符合退票时间规则时退票；开车前 8 天及以上不收退票费，开车前 48 小时以上按 5% 收取。请提供订单号或在我的订单中选择退票，系统会按订单明细计算最终退款金额。”

### 13.2 未命中知识库时

当知识库没有结果时，智能客服不应假装查到了资料。可以说明暂未检索到相关知识，并给出通用建议或转人工。

建议模板：

> 我暂时没有在知识库中检索到完全匹配的规则。你可以换一种问法，或提供订单号、车次、乘车日期等信息，我会继续帮你判断。

### 13.3 涉及隐私时

用户可能输入身份证号、手机号、订单号等敏感信息。客服回复应避免要求用户重复提供完整敏感信息。

安全建议：

- 可以要求订单号，但不要要求身份证完整号码。
- 展示手机号、身份证号时应脱敏。
- 查询订单必须基于当前登录用户。
- 不得帮助用户查询他人订单或实名信息。

## 十四、后台知识库管理说明

管理员可以在后台上传 Markdown、Word、PDF 或纯文本文件。文件上传后会生成入库任务，任务经历解析、切片、向量化和完成等状态。

管理规则：

- 分类用于组织知识，例如“退票规则”“支付问题”“购票流程”。
- 文档上传后会保存文档记录。
- 切片内容会写入数据库，并生成向量。
- 管理员可以查看切片创建时间、内容、文档 ID 和向量维度。
- 管理员修改切片内容后，应重新生成该切片向量。
- 入库失败时可以查看错误信息并重试任务。

常见排查：

- 如果知识库检索不到内容，先确认文档入库任务是否完成。
- 如果任务失败，查看解析器类型和切片模式是否正确。
- Markdown 建议使用 `MARKDOWN` 解析器和 `structure_aware` 切片。
- Word/PDF 建议使用自动识别或 `TIKA` 解析器。
- 本地向量模型未启动时，向量化任务可能失败。
